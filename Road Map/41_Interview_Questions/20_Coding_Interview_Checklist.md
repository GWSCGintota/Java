# Coding Interview Checklist

Use these as revision prompts. Try answering each question aloud before opening the answer.

## 1. Before coding, what should you do?

**Answer guide:** Clarify inputs, outputs, constraints, edge cases, and expected complexity.

## 2. How should you explain a solution?

**Answer guide:** Start with a simple approach, then improve it and justify the complexity tradeoff.

## 3. What edge cases should you consider?

**Answer guide:** Empty input, null where applicable, one element, duplicates, negatives, overflow, sorted/reversed input, and very large input.

## 4. What should you say while coding?

**Answer guide:** Explain intent at a useful level: data structure choice, invariants, complexity, and tricky cases.

## 5. What should you do after coding?

**Answer guide:** Dry-run examples, test edge cases, check complexity, and correct naming or off-by-one mistakes.

## 6. What Java topics should be automatic?

**Answer guide:** Collections, loops, strings, arrays, maps/sets, comparators, queues/stacks, exceptions, and basic streams.

## 7. What complexity should you state?

**Answer guide:** Time complexity and auxiliary space complexity.

## 8. When should you avoid Streams?

**Answer guide:** When an imperative loop is clearer, when mutation/control flow is central, or when performance/debugging would become harder.

## 9. What matters more than cleverness?

**Answer guide:** Correctness, clarity, reasoning, testability, and appropriate complexity.

## 10. What should you practice repeatedly?

**Answer guide:** Arrays/strings, hash maps, two pointers, sliding window, stack/queue, trees, graphs, recursion/backtracking, heaps, and dynamic programming.
